# Open-core removal map (before removal)

- `dispatch/usage/`: six reader implementations feed `registry` and `evaluate`; `config` and `preemptive` are imported by `dispatch/routing.py` and `dispatch/runner.py`. `adapters.py` validates reader names; preset JSON assigns readers. `onboarding.py` loads usage configuration for doctor. Matching usage reader, ranking and preemptive tests cover these paths.
- `codex_standalone_usage.py`: imports usage configuration, threshold evaluation and Codex reader. `codex_hook.py` prefetches during session setup and appends reserve warnings at stop. Standalone usage tests, hook reserve tests and test isolation helper reference it.
- Worker handoff: `dispatch/cli.py` parses `--on-limit`; MCP `server.delegate_task` forwards `on_limit` to `runner.run_task`. `proc.spawn_foreground` accepts a polling callback and kills the process tree on a handoff action. Runner performs preflight/periodic usage evaluation, checkpoints via `memory_lifecycle.py`, builds successor prompts, routes successors and transfers worktree leases. `store.py` stores attempts/handoffs and implements `transfer_worktree_lease`; CLI/server render handoff blocks. `limits.py` reactive classification/cooldown remains free.
- `dispatch/publish.py`: runner calls automatic PR publication after completion; orchestration models and manage config accept `onComplete=pr`. The completion sink imports `public_task` solely for privacy filtering; that filter must remain available independently of PR creation. Matching publication tests move out.
- `remote_queue.py`: manage `submit`, `worker` and remote `status` import queue submission, worker loops and status lookup. Queue tests and remote orchestrator tests reference these paths.
- README and GitHub Pages advertise handoff; README also describes usage readers and automatic PRs. Historical live-handoff evidence is paid-feature documentation.

Scope interpretation: the brief names `remote_queue.py` and its CLI commands, so existing SSH fact/truth synchronization in `bridge.py` is retained. Reviewer should confirm whether a later split should also move that independent synchronization surface. The private platform repository is untouched.

## Call chains

| Paid surface | Callers and removed call chain |
| --- | --- |
| Usage readers | `registry.read_usage_for_adapter` / `safe_read` -> Codex, Claude, Grok, Antigravity, Cursor, OpenCode Go readers -> shared result/window types; `evaluate_adapter_threshold` -> `evaluate.evaluate_threshold`; readers import `common` helpers and `types`. |
| Routing usage | `routing.select_agent` -> `load_usage_config`, `preemptive_usage_active`, `preflight_skip_reason`, `evaluate_adapter_threshold` -> hottest-window/headroom score and usage reason suffix. |
| Dispatch usage | `runner.run_task` and `supervise_job` -> `load_usage_config`, preflight skipping and threshold evaluation; `_ensure_spawnable_agent`, `_spawn_skip_reason`, `_record_usage_evaluation`, `_evaluate_and_check_usage` -> periodic `proc.spawn_foreground` callback and public usage metadata. |
| Worker transfer | `_reactive_handoff_prompt` / `_successor_handoff_prompt` and `_transfer_to_successor` -> memory checkpoint lookup, `memory_lifecycle.ensure_in_progress_checkpoint`, successor `select_agent`, `store.transfer_worktree_lease`; CLI `fmt_job` and server `_fmt_dispatch_job` render handoff/usage metadata. |
| Codex reserve | Hook `_handle_session_start` -> `_maybe_prefetch_codex_usage` -> standalone `usage_checks_enabled` / `prefetch_usage`; `_handle_stop` -> `_maybe_warn_codex_reserve` -> `maybe_append_reserve_warning` -> usage config/evaluation/Codex reader. |
| Doctor/config | `adapters.AdapterConfig` validates usage reader names; user `agents.json` and all seven reader-enabled presets carry usage settings; `onboarding.doctor` -> `_usage_mode_for_adapter` / `_usage_reason_for_adapter`; `manage._print_doctor` renders them. |
| Automatic PR | `runner._publish_if_requested` -> `publish.open_pull_request` -> completion mode / review gates / safe task extraction / Git and gh commands; global and per-project `onComplete`, plus `MINDSYNC_ON_COMPLETE`, select PR mode. `sink.public_completion_projection` also imports `publish.public_task` for privacy filtering, which stays as an independent local filter. |
| Remote queue | `manage.main` worker -> `RemoteQueue`, `run_worker_once`, `run_worker_loop`; submit -> `RemoteQueue.submit_job`; status -> `RemoteQueue.get_status` / list. Queue internally executes local `runner.run_task`, execution-mode validation and optional commit workflow. `config.Settings` parses remote-worker ID, polling, stale-claim, orchestrator permission and allowed-root environment settings; those unused fields and the `.env.example` worker block are removed, with deferred Pro errors for legacy environment settings. |

Matching paid tests removed: `test_usage_readers*`, `test_usage_preemptive`, `test_codex_standalone_usage`, `test_dispatch_publish`, `test_remote_queue`, `test_remote_orchestrator`; paid cases removed from hook/routing/limits/onboarding suites. Free classification, cooldown, worktree, memory, routing and notification privacy tests remain.
